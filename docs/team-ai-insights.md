# Team AI analytics

Second AI feature, inside My team. Only an active company team lead with team.self.read, leads.read, pipeline.read and tasks.read can inspect or analyze their current team. No company/team/member IDs are accepted as scope inputs. Company owners, agents and platform workspace sessions cannot call these endpoints.

- GET /api/v1/team/my-team/ai-insights/snapshot?days=7|30|90: full-team recorded metrics, source/stage breakdowns, daily trends, current members and workload, plus the preceding equal period. Counts follow current membership/ownership, not a historical roster. Open pipeline is recorded sale value; lease/unknown values are separate. Won/lost are current lead stages changed in the requested Cairo period, not immutable transaction history.
- GET /api/v1/team/my-team/ai-insights?days=30&language=en: {run:null} or the latest private run for this team lead, range and language. Never calls AI.
- GET /api/v1/team/my-team/ai-insights/:runId: private job status/results, with current access and source-change checks.
- POST /api/v1/team/my-team/ai-insights: {requestId:UUID,days:7|30|90,language:en|ar}. Starts an explicit background job. Same request IDs are idempotent; different inputs with a reused ID conflict. Identical successful results are reusable for ten minutes. One active job per user, ten paid attempts/hour/user and sixty/day/company. Every new job is audited before calling Kimi. No automatic paid retry; interrupted jobs expire after three minutes.

Kimi thinking remains enabled. Only aggregate metrics, dates and anonymous member keys are transmitted. No names, email addresses, phone numbers, company/team identifiers, lead/task titles or notes. Team totals include all members. Member-focused AI analysis is bounded to the twenty members with the most open work; the dashboard discloses coverage. AI output is strict JSON with bounded text, valid evidence metric IDs and anonymous member keys from this snapshot. Narrative contains no numeric claims; the dashboard renders the actual evidence values from the database. Suggestions do not update assignments, tasks, stages, scores or staff access. Results become stale when relevant data, membership, account status or the reporting day changes.

Failure states include missing configuration, provider timeout/quota, invalid evidence/output, changed data and interrupted jobs. Existing regular team analytics remains usable if AI fails. API-process jobs persist their state but do not resume automatically after a restart. Tests exercise the actual Kimi HTTP adapter against a local provider fixture as well as tenant authorization, source metrics, idempotency, stale results and failure behavior.

Team analysis allows up to two minutes for a provider response (unit recommendations retain their existing one-minute default). No automatic retries are made.
