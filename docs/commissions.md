# Company commissions

Migration 018 upgrades existing/new company owners with commissions.read/manage. All endpoints require current subscription access and trusted company scope. GET /api/v1/commissions supports search/status/pagination, actual status totals and forecast/recalculation flags; /options returns actual active company payees; /:id returns the saved split and manual recording details.

POST /commissions calculates from an actual company contract with its current version, rateBps (1–10000) and distinct payee shares totaling 10000 basis points. Requires contracts.read. Null payee means Company share; other payees must be active company users. There are no invented agents or team leaders. Gross rounds half up to the nearest minor unit; split floors plus largest remainders (stable input-order ties) guarantee exact total allocation. All money remains integer strings, including values above JavaScript safe integer precision. One commission exists per contract.

Calculated commissions on unsigned contracts are explicitly forecasts. /:id/recalculate can revise a current calculated or canceled record for a non-void contract; it snapshots the current agreed value and resets approval/payment state. A contract value change is flagged and blocks approval until recalculation.

/:id/action supports approve, mark_payable, record_paid and cancel, with current version and a reason of 10–500 characters. Approval requires the stored contract to be signed and the value snapshot current. Payable requires an approved record and a current receipt file linked to the same contract or lead. Recording paid requires payable status, receipt evidence, an external reference and an actual nonfuture payment date. These are manual evidence/payment records, not bank transfers, collection or payment-provider verification. Split amounts are saved, not electronically disbursed.

Calculated, approved and payable records can be canceled; paid records cannot be canceled or rewritten. A canceled record may be recalculated and must pass approval again. Voiding a contract cancels its calculated forecast atomically. Approved/payable commissions must be canceled first; a paid commission blocks voiding and requires a future financial reversal workflow. Receipt files supporting payable/paid records cannot be archived. No deletion or automatic reversal is claimed.

State, audit, outbox, lead activity and replay responses commit or roll back under the shared company write lock. RLS and composite foreign keys prevent cross-company contracts, actors and receipt evidence. The dashboard replaces preview amounts/people with server calculations, actual payee choices, receipt selection/upload links and explicit manual recording dialogs.

Run npm run db:seed:commissions with isolated migration credentials, or node scripts/seed-commissions.mjs --company-slug=your-slug in maintenance. Default targets are only the three labeled sample companies with current subscriptions. It ensures the sample draft agreement and inserts one labeled calculated forecast at 2.5%, entirely allocated to Company share. Reruns preserve existing canceled/edited/paid records and create no fake approvals, payments, signatures or people. No new environment secrets are required.

Migration 020 enforces the existing effective feature policy: commission management requires `commissions`; weighted/team routing and any first-contact SLA require `routing_adv`. The global switch, current trial/active company and subscription, plan matrix, stable rollout and unexpired company overrides apply server-side. Basic round-robin/specific-user routing with zero SLA remains core functionality. Disabled advanced routing skips those rules and stops SLA reassignment; historical assignments remain.
