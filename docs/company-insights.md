# Company reports, audit log and overview

Migration 020 connects all remaining company screens. Restricted runtime roles and forced tenant RLS apply. Owners receive `reports.read`, `reports.export`, `audit.read`; no platform permissions. All endpoints also require a current accessible company and subscription. Overview requires `workspace.view` and redacts module data without its read permission; commission amounts additionally require `commissions.read` and the effective feature entitlement, including in reports/CSV.

- `GET /api/v1/reports?period=month|quarter|ytd&segment=res|com`: consistent read snapshot, Cairo calendar bounds, retained lead cohorts including archived leads, their current mutually exclusive stages/source won rate, currently signed sale agreements by external signed date, exact minor-unit amounts. Voided agreements are excluded. Zero months remain zero; no leads means unknown conversion. Owner table reflects current lead assignees and contract owners (top 100 plus unassigned). No historical funnel-transition inference or cash-revenue claim.
- `POST /api/v1/reports/export`: same period/optional segment, language en/ar, UUID requestId. Requires read and export permissions. Returns UTF-8 CSV with exact currency strings and formula-neutralized cells; shared replay ledger prevents duplicate audit events. Only period/window/segment metadata is audited, never the CSV. Browser downloads the real result.
- `GET /api/v1/company-audit`, `/options`, `/:uuid`: actual append-only tenant audit history, sanitized before/after, actor/system, resource, actual timestamp and optional IP. Filters q/actor/action/from/to, Cairo-inclusive calendar dates. Limit 1–100, opaque keyset cursor preserves PostgreSQL microseconds and UUID tie ordering. Tenant runtime cannot rewrite history; list total covers all matches, not the loaded page. No synthetic history is seeded.
- `GET /api/v1/company-overview?segment=res|com`: open sale pipeline (lease count separate), recorded paid commissions this Cairo month, open tasks due today, new retained leads last 7 calendar days, top manual scores, contract key dates next 14 days, current quarter signed sale chart. Inventory/project counts remain company-wide. Segment filters linked-lead data; general tasks appear only in all-segments. Alerts derive overdue open tasks, missing required evidence, reservations expiring within 24h, payable commissions, eligible first-contact SLA and observed routing-worker heartbeat. No forecast close dates, targets, automated scoring or fake activity.

Premium commission management and advanced routing use the narrow `platform.company_feature_access` security-barrier view filtered to the trusted tenant GUC; no platform base-table grants. Global kill switch, current trial/active company/subscription, plan matrix, SHA rollout and valid company override all apply. Basic fixed reports are core; `reports_adv` is not an implemented custom report builder. Existing paid records remain in storage when access is disabled and are hidden from read APIs.

## Initial data and deployment

`npm run db:seed:company-insights` composes the idempotent Tasks, Contracts/Documents, Commissions and Marketing/Routing seeds and their source dependencies. Default scope is the three named sample companies; optional `--company-slug=...` explicitly opts another company in. It preserves edits, archived/closed states, creates no accounts/passwords, and does not fabricate signed contracts, paid money, contact activity or enabled routing. Reports and overview aggregate these persisted sample records; audit entries come from actual seed operations. Consequently a zero signed-sale chart is valid until a real signed sale is recorded. Feature access is configured explicitly through the admin policy controls, never silently changed by a seed.

Deploy backend first (migration then API and worker health), then dashboard. No additional environment secrets or `.env` keys are needed. Staging verification uses disposable companies with temporary feature overrides and archives those companies afterward. Main is unchanged.
